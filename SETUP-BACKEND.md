# ECET backend setup

1. Open the Google Sheet configured in `Code.gs` and open **Extensions → Apps Script**.
2. Replace the existing `Code.gs` with the supplied `Code.gs` from this package.
3. Save the project.
4. Run the `setup()` function once from the Apps Script editor and approve the requested permissions. It creates/updates these sheets:
   - Users
   - Results
   - Answers
   - WrongAnswers
   - Rankings
   - RevisionHistory
   - EmailQueue
   - SubmittedSessions
   - Reminders
   - Notifications
5. `setup()` also creates time-based automation for result-email retries, reminder delivery, and revision-unlock emails.
6. Deploy **Deploy → New deployment → Web app**. Execute as the spreadsheet owner and choose the appropriate access setting for your users.
7. Copy the deployed `/exec` URL into `config.js` as `APPS_SCRIPT_URL`.
8. Upload the complete site files to your hosting location.

## Important behavior

- Main-test scoring has **no negative marking**: marks = correct answers.
- Main-test time = **60 seconds per question**.
- Wrong and unattempted questions are both stored as revision mistakes with `MistakeType` = `wrong` or `unattempted`.
- Revision unlock time is one day after the original main-test submission.
- The initial result email shows the unlock date when revision is still locked. A separate unlock email is sent when the revision becomes available.
- Every main-test submission creates a new Results row. Retakes never overwrite previous attempts.
- Reminder emails are generated by the `processReminders` trigger. The UI stores the user's registered email automatically.
- Notification failures are retained in `Notifications` and can be retried from the website.

## Existing sheets

The script adds missing columns to existing sheets. It does not intentionally delete old data. If you already have older columns, keep them; the new columns are appended during `setup()`.
